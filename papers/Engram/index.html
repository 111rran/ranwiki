    Engram 论文解读

    作者：东川路第一可爱猫猫虫

    一、主要内容概览

    本文围绕 Engram（条件记忆机制）展开，核心论点：大语言模型（Large Language Model, LLM）在处理静态知识（如命名实体、固定搭配）时，浪费了宝贵的计算资源去做"检索式查表"就能完成的工作。Engram 正是为解决这一问题而设计的。

    • LLM 用计算模拟检索 —— 为什么当前的 Transformer 架构低效
    • N-gram —— 从经典统计语言模型到现代 N-gram Embedding 的演进
    • Engram 的流程 —— 分词器压缩（Tokenizer Compression）、多头哈希（Multi-Head Hashing）、上下文感知门控（Context-aware Gating）
    • Engram 的优化 —— 与多头哈希链（mHC）的适配、基于 MoE 的解耦计算与记忆、多级缓存
    • Engram 的实验 —— 槽位规模效应、参数分配策略、最优放置层

    二、背景：条件计算与 MoE

    2.1 MoE（Mixture of Experts，混合专家模型）

    MoE 的核心思想是稀疏性和条件计算： - 不是所有参数都对每个输入起作用，每次只激活一部分"专家"（Expert） - 通过门控网络（Gating Network / Router）根据输入动态选择激活哪些专家 - 这大幅增加了模型总参数量，但保持推理计算量可控

    MoE 的成功证明了：语言建模中并非所有子任务都需要同等计算资源。

    2.2 语言建模的两个子任务

    语言建模可以分解为两个性质截然不同的子任务：

    子任务 特点 需求
    组合推理（Compositional Reasoning） 需要理解语法结构、逻辑关系、上下文推理 需要计算（Computation）
    知识检索（Knowledge Retrieval） 命名实体、固定搭配、公式化词组等静态事实 需要记忆（Memory）

    核心洞察：当前 LLM 用同一套 Transformer 层同时处理这两种任务，导致大量计算被浪费在"死记硬背"静态知识上。

    三、问题：LLM 如何理解多 Token 词组？

    3.1 案例分析

    以词组 "Diana, Princess of Wales"（威尔士王妃戴安娜）为例：

    • 这是一个常见的、静态的多 Token 知识
    • 用 PatchScope（一种可解释性工具，能将 LLM 在每一层的中间表征翻译为自然语言）逐层观察：
    • LLM 需要经过多层注意力机制和多层前馈网络（FFN） 的复杂计算，才能成功将一个多 Token 词组解析为完整概念
    • 一个众所周知的静态事实，竟然消耗了六层网络的计算深度

    3.2 本质问题

    LLM 本质上是在用计算来模拟检索（Simulate Retrieval through Computation）

    明明可以通过静态查表（Static Lookup）直接获取的知识，大模型却进行了昂贵的运行时重建（Expensive Runtime Reconstruction）。宝贵的序列深度（Sequence Depth）被浪费在了这类低价值的计算上。

    四、N-gram 的重新审视

    4.1 什么是 N-gram？

    N-gram 是自然语言处理中的经典概念，指文本中由 N 个连续单词（或 Token）组成的序列：

    • Unigram（一元词组）：单个词，如 "Diana"
    • Bigram（二元词组）：两个连续词，如 "Princess of"
    • Trigram（三元词组）：三个连续词，如 "Diana, Princess of"

    4.2 经典用法 vs 本文用法

    经典 N-gram 语言模型 本文的 N-gram Embedding
    用途 统计词序列概率，用于语言建模 将 N-gram 存储为可检索的向量嵌入
    存储 概率表（计数 + 平滑） 高维向量嵌入表
    目标 预测下一个词的概率 直接将常见词组的语义向量注入模型

    本文的核心思路：把像 "Diana, Princess of Wales" 这样的常见 N-gram 的语义向量预先存储起来，供模型直接查找，省去重复计算。

    4.3 为什么现在重提 N-gram？

    三个动机叠加：

    1. MoE 已验证稀疏性有效 —— 条件计算的思路已获认可，条件记忆是自然的延伸
    2. 静态知识的计算浪费被量化 —— 可解释性工具让我们看到了"浪费"的具体程度
    3. 硬件架构提供了可能 —— GPU HBM、Host DRAM、NVMe SSD 构成的存储层级，使大规模记忆表的硬件可行性成熟

    五、Engram 的核心流程

    Engram 的核心设计围绕三大组件：

    5.1 分词器压缩（Tokenizer Compression）

    问题背景：传统 Embedding 词嵌入方式中，分词器（Tokenizer）要求无损重建（Lossless Reconstruction），即从 token ID 必须能精确还原原始文本。这导致：

    • "Apple"、"apple"、"␣apple"（带前导空格）被视为三个完全不同的 token
    • 分词算法对大小写、空格、特殊字符极其敏感
    • 词表（Vocabulary）中存在大量冗余条目，造成了词表浪费

    Engram 的做法：对分词器进行压缩优化，减少 token 空间的冗余，让 N-gram 查表更加高效。通过归一化处理（如小写化、去除冗余空白符），将语义相同但形式不同的 token 合并，缩小 N-gram 组合的搜索空间。

    5.2 多头哈希（Multi-Head Hashing）

    这是 Engram 最核心的技术组件，解决了一个关键矛盾：直接参数化所有可能的 N-gram 组合在计算上是不可行的。

    问题分解：

    步骤 问题 解决方案
    第一层 所有可能的 N-gram 组合空间太大，无法全部存储 哈希映射（Hash Mapping）：用有限槽位承载所有词组，将高维 N-gram 空间压缩到固定大小的表中
    第二层 有限槽位导致哈希冲突（Hash Collision）——语义不同的词组被映射到同一槽位，互相干扰 多头哈希（Multi-Head Hashing）：为每个 N-gram 阶数 n 使用 K 个不同的哈希函数头

    多头哈希的直觉：

    "单点可能出错，但多点难以同时出错。"

    即使某个哈希头将两个不相关的词组映射到了同一个槽位（冲突），其他哈希头几乎不可能也产生同样的冲突。通过多个哈希头的冗余编码和结果聚合，系统鲁棒地降低了冲突带来的信息损失。

    公式化描述： - 给定一个 N-gram 序列 s，通过 K 个独立的哈希函数 h₁, h₂, ..., h_K 映射到槽位表中 - 每个哈希头产生一个槽位索引，取出对应的嵌入向量 - 所有 K 个头的输出通过可学习的方式聚合（如加权求和或注意力聚合）

    5.3 上下文感知门控（Context-aware Gating）

    并非所有 N-gram 在所有上下文中都同等重要。上下文感知门控机制根据当前上下文动态决定：

    1. 是否触发记忆检索 —— 某个 N-gram 在当前语境下是否值得查表
    2. 记忆权重大小 —— 检索到的记忆向量以多大的强度注入当前层的表征

    这个门控机制类似于 MoE 中的 Router，但作用对象不是"专家"，而是"记忆槽位"。它学习判断：当前上下文中，模型是更应该依赖自身的计算能力（推理），还是更应该依赖外部记忆（检索）。

    六、Engram 的优化策略

    6.1 与 mHC（Multi-Head Hash Chains）的适配

    mHC（多头哈希链）是 Engram 的记忆组织结构： - 将多个哈希头串联成链式结构 - 逐级细化检索结果，前一级的粗筛结果指导后一级的精确检索 - 与 Engram 的门控机制协同，形成从"定位"到"筛选"到"注入"的完整记忆管线

    6.2 解耦计算与记忆：时间管理大师

    这是 Engram 在系统层面的重要优势，利用了计算与记忆之间的确定性差异：

    对比维度 MoE Engram
    路由依赖 路由依赖于上一层的计算结果 查表索引仅取决于输入 Token 序列
    可预取性 不能预先加载专家（不知道路由结果） 索引在计算开始前就已确定，可提前准备
    并行性 必须等待前一层计算完成 可以与前面层的计算并行执行

    异步预取（Asynchronous Prefetch）： - GPU 在计算 Transformer 前面层的同时，CPU 就可以提前将 Engram 所需的数据从存储介质搬运到 GPU 内存 - 前面层的计算天然充当了延迟缓冲区，有效掩盖了数据传输延迟

    掩盖延迟（Latency Hiding）： - GPU 不会因为等待数据而停顿（Stall） - 计算和数据传输形成流水线，最大化硬件利用率

    6.3 多级缓存（Multi-Level Caching）

    自然语言中的 N-gram 分布遵循 Zipf 定律（齐普夫定律）：

    约 20% 的词汇出现了 80% 的次数（长尾分布）

    基于这一统计规律，Engram 设计了分层存储架构：

    存储层级 介质 速度 容量 存储内容
    热数据层 GPU HBM / Host DRAM 极快 有限 高频词（Top 20% 的常用 N-gram）
    冷数据层 NVMe SSD 较慢 极大 长尾罕见词（长尾分布的剩余部分）

    这种设计使 Engram 能够扩展到巨大的内存容量，而对有效推理延迟的影响最小。

    七、实验分析

    7.1 记忆槽位越多越好吗？（无限内存机制）

    实验设计：在计算量不变、模型结构不变的前提下，将 Engram 的记忆槽位数量从 25.8 万个逐步增加到 1000 万个，观察模型性能变化。

    关键发现： - Engram 模型的 KL 散度（Kullback-Leibler Divergence，衡量预测分布与真实分布之间的差异）下降速度显著快于 MoE 基线，尤其在前几层 - 这表明 Engram 的记忆机制在模型早期就提供了高质量的知识，减少了后续层的信息重建负担

    7.2 CKA（Centered Kernel Alignment）分析

    CKA（中心核对齐）是一种衡量两个神经网络层表征相似度的指标： - 数值越高，表示两个层的内部表征越相似

    实验结果： - 原本 MoE 模型需要经过很多层计算才能获得的知识表征 - Engram 模型在浅层就已完成等价的知识获取（CKA 值与 MoE 深层对齐）

    这验证了 Engram 的核心假设：静态知识不需要深度计算，查表即可获得等价表征。

    7.3 参数分配策略

    Engram 并非要替换 MoE，而是与 MoE 协同工作。关键问题是：

    模型总参数量如何在 MoE（计算）和 Engram（记忆）之间进行最优分配？

    实验探索了两者之间的最优配置比率，寻找在固定参数预算下最大化模型性能的"甜区"（Sweet Spot）。

    7.4 Engram 放在哪一层最好？

    两股力量的权衡（Trade-off）：

    视角 偏好 原因
    系统角度 放深一点（靠后的层） 前面的层越多，GPU 计算时间越长，留给 CPU 异步预取的时间窗口越充裕
    模型角度 放浅一点（靠前的层） 越早注入外部知识，越能为模型省下"死记硬背"的计算开销，效果越好

    结论：需要在模型性能和系统延迟之间进行工程权衡，确定最优放置位置。通常选择中间偏前的层作为工程上的折中方案。

    八、总结

    Engram 提出了一种条件记忆（Conditional Memory）机制，核心思路：

    1. 识别分离 —— 语言建模中的"推理"和"检索"是两个不同任务，应当分别处理
    2. 以存代算 —— 将静态 N-gram 知识预先存储为向量嵌入，避免重复计算
    3. 高效检索 —— 通过多头哈希 + 上下文感知门控，在有限槽位内实现鲁棒的记忆存取
    4. 系统协同 —— 利用确定性索引实现异步预取，配合多级缓存在不增加延迟的前提下扩展记忆容量

    Engram 本质上是对经典 N-gram 语言模型思想在现代深度学习框架下的系统性升级，为 LLM 的高效知识存储与检索提供了新范式。
